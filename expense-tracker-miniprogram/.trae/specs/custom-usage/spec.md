# 常用账单自定义用途 - 产品需求文档

## 概述
- **摘要**: 为"极简账簿 - 大学生记账助手"的常用账单功能添加自定义用途支持，让用户可以更灵活地使用常用账单，支持一个常用账单对应多个用途/分类，大幅提升记账的灵活性和便捷性。
- **目的**: 解决当前常用账单只能固定一个分类的限制，让用户可以根据实际情况快速选择不同的用途，例如"早餐"常用账单可以快速选择是"包子"、"豆浆油条"、"面包牛奶"等不同的具体用途。
- **目标用户**: 在校大学生、有日常固定消费但具体用途多变的年轻用户群。

## 目标
- 支持常用账单添加多个自定义用途选项
- 在快速记账时可以快速选择不同的用途
- 每个用途可以预设不同的金额、备注等信息
- 保持操作的简洁性和高效性
- 支持用途的添加、编辑、删除管理

## 非目标 (范围外)
- 不实现基于历史记录的智能用途推荐
- 不实现用途的自动学习功能
- 不实现用途的批量导入导出

## 背景与上下文
- 现有常用账单功能已经实现，但每个常用账单只能固定一个分类和金额
- 用户在实际使用中，同一类账单可能有不同的具体用途（如早餐可以是包子、豆浆、面包等）
- 从用户提供的截图可以看到，用户希望有类似"餐饮、购物、交通、娱乐"这样的分类选择方式
- 项目已具备完善的常用账单管理功能，有良好的代码结构基础

## 功能需求
- **FR-1**: 常用账单支持添加多个用途选项
- **FR-2**: 每个用途可以设置独立的金额、备注信息
- **FR-3**: 在首页快速记账时，点击常用账单后显示用途选择弹窗
- **FR-4**: 在记账页面快捷选择常用账单时，支持用途选择
- **FR-5**: 在常用账单管理页面，支持用途的添加、编辑、删除
- **FR-6**: 支持直接使用默认用途（不显示选择弹窗，快速记账）
- **FR-7**: 用途数据持久化存储

## 非功能需求
- **NFR-1**: 用途选择操作流畅，响应时间小于500ms
- **NFR-2**: 用途管理界面简洁易用，符合现有设计风格
- **NFR-3**: 支持可访问性功能（高对比度、减少动画等）
- **NFR-4**: 一个常用账单最多支持20个用途选项

## 约束条件
- **技术**: 使用微信小程序原生框架，不引入额外的第三方UI库
- **业务**: 保持与现有常用账单功能的数据结构兼容
- **依赖**: 依赖现有的 utils/quickBills.js 工具模块

## 假设条件
- 用户希望常用账单更加灵活，能适应不同的具体场景
- 用户愿意花时间设置自己的常用用途
- 用途选择弹窗不会显著增加操作复杂度
- 用户可以根据个人习惯选择是否启用用途选择功能

## 验收标准

### AC-1: 常用账单用途管理
- **给定**: 用户进入常用账单管理页面
- **当**: 用户为某个常用账单添加、编辑或删除用途
- **则**: 操作成功后数据正确保存，并在用途列表中正确显示
- **验证**: `programmatic`
- **备注**: 每个用途应包含名称、金额、备注等信息

### AC-2: 首页快速记账用途选择
- **给定**: 用户在首页点击常用账单
- **当**: 该常用账单有多个用途时
- **则**: 显示用途选择弹窗，用户选择后保存账单
- **验证**: `human-judgment`
- **备注**: 弹窗设计应简洁易用

### AC-3: 默认用途快速记账
- **Given**: 用户设置了某个常用账单使用默认用途
- **When**: 用户在首页点击该常用账单
- **Then**: 直接使用默认用途保存账单，不显示选择弹窗
- **验证**: `programmatic`

### AC-4: 记账页面用途选择
- **Given**: 用户在记账页面选择常用账单
- **When**: 该常用账单有多个用途时
- **Then**: 显示用途选择界面，用户选择后自动填充表单
- **验证**: `human-judgment`

### AC-5: 数据持久化
- **Given**: 用户已设置常用账单的用途
- **When**: 关闭小程序后重新打开
- **Then**: 用途数据保持不变
- **验证**: `programmatic`

### AC-6: 界面一致性
- **Given**: 用户使用用途相关功能
- **When**: 浏览各个相关页面
- **Then**: 界面风格、颜色、动画与现有页面保持一致
- **验证**: `human-judgment`
